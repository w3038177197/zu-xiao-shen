# 小程序联网 AI 实现与部署清单

小程序默认优先联网 AI，首次发送联网请求前单独征得用户同意；用户拒绝、未授权或服务不可用时自动使用本地分析。模型密钥、微信 AppSecret 和会话签名密钥均不得写入小程序包或提交到 Git。

## 已实现

- 默认优先联网，首次联网单独确认；确认后建立短期会话并同步当日额度，发送时直接复用。
- `wx.login` 换取服务端短期签名会话，401 时最多刷新一次。
- 当前问题默认单独发送；用户可逐项选择合同审查、验房、证据包和补贴模块，并在发送前预览实际文本。
- 合同模块只携带风险标题、相关条款片段和建议；验房只携带瑕疵文字；证据包只携带清单、附件名称和缺口，不发送合同全文、照片内容、附件文件或本地路径。
- 资料摘要在本机先脱敏，服务端再次脱敏；客户端支持取消、超时、手动重试、额度提示、本地降级和连续故障短暂熔断。
- 服务端固定系统提示词、二次脱敏、知识库检索、限流、每日额度与 `requestId` 幂等缓存；可选接入 Upstash Redis REST，使额度和成功回答缓存跨服务重启保留。
- 联网回答显示"AI生成"，复制时自动附加 AI 内容提示。
- 首次联网前先读取 `/api/health`：旧后端、微信登录未配置或模型密钥缺失时显示可执行状态，并直接保留本地回答，不再让用户遇到模糊的 404。

## 调用链

1. 小程序 `wx.login` 获取临时 code。
2. 服务端调用 `code2session`，签发短期会话令牌；令牌只放在小程序本地存储。
3. 小程序请求 `POST /api/miniapp/ai/chat`，携带会话令牌、当前问题和用户逐项选择且已经预览的业务资料摘要。
4. 服务端校验会话、额度、请求体大小和速率后调用模型；响应只返回文本、引用和用量。
5. 小程序收到超时、401、429 或 5xx 时保留本地模式，并提供明确的重试入口。

## 请求约束

```json
{
  "requestId": "zxs_xxx_xxx",
  "prompt": "房东要求扣保洁费怎么办？",
  "history": [],
  "contextSummary": "【合同审查】合同评分 61 分，共 3 个风险点……"
}
```

请求体不接受合同全文、照片路径或附件文件。客户端和服务端都会脱敏手机号、身份证号、银行卡号、邮箱、姓名和详细地址，且服务端不持久化问题正文。业务摘要最多 6000 字；按微信用户维度限制每日次数、单次长度和并发数，额度耗尽时返回 `429` 与本地降级提示。

## 取消、重试和审计

- 每次请求生成 `requestId`，客户端支持取消；服务端超时后主动终止上游请求。服务端同时绑定已脱敏请求指纹，相同 ID 只有在内容一致时才允许重放，避免异常复用 ID 返回旧问题答案。
- 401 只刷新一次短期会话；其他可恢复错误由用户点击“重试联网”，不自动重复请求。
- 连续三次网络、超时、证书或 5xx 故障后，客户端暂停普通联网请求 30 秒，直接给出本地回答；用户仍可通过“重试联网”主动探测恢复。
- 日志只记录 `requestId`、耗时、状态码和 token 用量，不记录合同正文。
- 上线前配置 HTTPS 合法域名、已通过的隐私保护指引、用户数据删除入口和模型服务商数据保留策略。

## 验收标准

- 无网络时本地 AI 仍可用，远程失败不白屏、不丢草稿。
- 未登录、额度耗尽、超时、取消和服务端错误均有可理解的界面反馈。
- 真机弱网下不会重复扣额度；同一个 `requestId` 至多计费一次。

## 微信云托管环境变量

后端部署在微信云托管，`server/` 改动发布前需要重新部署微信云托管。以下环境变量在微信云托管控制台配置：

| 变量 | 用途 |
| --- | --- |
| `WX_APPID` | 正式小程序 AppID |
| `WX_SECRET` | 小程序 AppSecret，仅在微信云托管后台填写 |
| `MINIAPP_SESSION_SECRET` | 至少 32 位随机会话签名密钥，仅在微信云托管后台生成 |
| `MINIAPP_SESSION_TTL_SECONDS` | 会话有效期，当前建议 `7200` |
| `DEEPSEEK_API_KEY` | 模型服务密钥 |
| `AI_DAILY_QUOTA` | 单个微信用户每日联网次数 |
| `UPSTASH_REDIS_REST_URL` | 生产环境必须配置；Upstash Redis REST 地址，用于持久化额度和幂等结果 |
| `UPSTASH_REDIS_REST_TOKEN` | 生产环境必须配置；与上项配套的服务端访问令牌 |

部署后还必须在微信公众平台配置微信云托管服务域名（或正式自有域名）为 `request` 合法域名。当前用户隐私保护指引已通过；正式开放联网 AI 前仍需确认其中已披露模型服务商的数据处理范围。

每次微信云托管重新部署后，在项目根目录执行 `npm run check:miniapp-deployment`。该命令会验证线上版本号、微信登录配置、模型密钥状态以及联网 AI、合同解析、OCR 三条受保护接口；任何一项仍是旧版本、404 或未鉴权都会退出失败。微信开发者工具已开启合法域名校验，模拟器不会再掩盖真机域名问题。

## 生产化后续

未配置 Upstash 时，额度和幂等缓存保存在单个服务进程内，微信云托管重启后会清空，仅适合本地开发和比赛演示。配置两项 Upstash 环境变量后，服务端使用原子脚本预占/回滚每日额度，并把成功回答按 `requestId` 缓存；微信身份只以 SHA-256 哈希进入键名。生产环境必须配置 Upstash Redis REST，`memory` 模式仅适合开发/演示。正式开放后仍应为模型调用成本、错误率和额度存储可用性增加监控。
